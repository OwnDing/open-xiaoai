## 本阶段内容

- **按设备配置**：后端 `data/.config.yaml` 新增 `voice_devices`，以 `Device-Id` 为键，支持四项：`output`（是否收服务端音频）、`tts`（TTS 模块）、`room`（房间）、`reply_style`（回答方式）。逻辑在 [voice_devices.py](../deploy/sherpa-tts/xiaozhi-server-overrides/voice_devices.py)，[patch_server.py](../deploy/sherpa-tts/xiaozhi-server-overrides/patch_server.py) 只加三处挂钩。代码里没有具体设备或房间，没有条目的设备行为不变。
- **房间上下文**：有 `room` 的设备，系统提示词的 `<context>` 里会多一行 `Device room`；Hermes provider 精简提示词时保留 `Device room` 和 `Reply style`。
- **完整句子回答**：`reply_style: sentence` 要求至少用一句完整的话回答，解决 P1 发现的单字回答听不清。
- **按设备 Edge TTS**：`tts: EdgeTTS` 的设备用在线 Edge 合成，其余设备仍用 Sherpa。
- 终端配置去掉 `room`，房间只在后端配置一处。

## 发现的问题：远程桌面占用本机音频

用户连着远程桌面时，蓝牙音箱完全不出声：终端、单独的播放进程、浏览器都一样，即使终端以 SYSTEM 身份运行在会话 0。Windows 端点状态正常、未静音，播放时电平表峰值约 0.49。断开远程桌面后立即恢复（08:23 和 08:26 的播放都听到了）。麦克风不受影响，所以唤醒仍能检测到。

P0.5 记录里 21:33 / 21:38 两次原因不明的失声，当时也有一个活动的远程桌面会话，很可能是同一原因。

处理：远程桌面客户端的“远程音频”设成“在远程计算机上播放”（mstsc：本地资源 → 远程音频 → 设置；Mac 的 Windows App / Microsoft Remote Desktop：Play sound → On the remote PC）。用户此前通过远程桌面播放浏览器音频时是有声音的，可能当时用的客户端或设置不同；下次连接时再验证。

另外：音箱重连后，Windows 端点音量从 49% 变成了 100%（蓝牙绝对音量同步），音箱实际音量由它自己的旋钮决定。

## Sherpa 与 Edge 对比（书房蓝牙音箱）

**合成耗时**（同一句话单独合成整句，不是对话里的出声延迟）：

| 句子 | 音频 | Sherpa | Edge |
| --- | --- | --- | --- |
| 明天宁波小雨，气温十八到二十二度，出门记得带把伞。 | 5.6 s | 0.76 s | 1.38 s |
| 书房灯已经帮你关掉了。 | 2.4 s | 0.31 s | 1.22 s |
| 现在是早上八点四十分，今天是十月五号，星期一，国庆假期第五天。 | 7.2 s | 2.99 s | 1.42 s |

**对话延迟**：同一问题“用两句话说说秋天的特点。”每种 3 次，从提问到第一个音频包的时间，Sherpa 中位数 1.36 s，Edge 2.33 s。Sherpa 边合成边推送；Edge 每句整段合成完才发送。

**盲听**：三句话分别用两种引擎合成，响度对齐，在蓝牙音箱上按 A / B 成对播放（终端开着麦克风，即实际使用的通话音质），不告知用户哪个是哪个。用户选 A（Edge），理由是音色和自然度更好。

**实际对话（Edge，6 轮）**：不查设备的问题 1.9～2.5 s 开始出声，查 Home Assistant 的 3.7～4.0 s（Sherpa 同类约 1.2～1.4 s 和 2.3 s）。后端日志确认都由 `core.providers.tts.base`（Edge）合成。用户认为多等约 1 s 可以接受，书房音箱改用 Edge 继续试用。

其他观察：窄带麦克风下仍有识别错误（“那空间置量”），这时模型会反问确认；只说“关机”时模型会追问是哪台设备，不会直接执行。

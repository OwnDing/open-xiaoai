## 结论摘要

1. **蓝牙麦克风只有 8 kHz 窄带。** WASAPI 输入采样率为 8000 Hz。P0 那段 16 kHz 录音在 4 kHz 以上的能量比 300–3400 Hz 低 55–77 dB，说明走的是 CVSD 窄带通话编码，16 kHz 只是升采样。适配器是 Intel，一般支持宽带语音，限制多半来自音箱。
2. **麦克风打开时播放降为窄带。** 麦克风关闭时，1、3、5、7、10 kHz 五声测试音都能听到；打开后只能听到 1–2 声。用户评价语音回答的音质与立体声模式“差不多”，可以接受；音乐会明显变差。
3. **音箱没有有效的回声消除。** 播放时麦克风录到的回放约 -17～-19 dBFS RMS，峰值约 -3 dBFS，1 kHz 测试音约 -7 dBFS。第一版必须在播放时暂停收音。
4. **底噪主要是低频嗡声。** 安静时原始底噪约 -29.8 dBFS（300 Hz 以下能量比人声频段还高 6 dB），只做高通就降到 -43.7 dBFS，WebRTC 降噪后约 -56 dBFS。
5. **指令识别可用。** 4 遍语料的平均错字率：不处理 11.7%，WebRTC 降噪 + 自动增益 10.7%。指令内容大体正确，错误主要来自唤醒词和句首漏读。
6. **本地唤醒不可用。** 用线上桥接的唤醒模型，20 次“你好小七”在默认阈值下只命中 2 次；最好的组合（WebRTC 降噪 + 自动增益，阈值 0.05）也只有 9 次。识别结果把“你好小七”听成“你好小西”“你好陕西”“你好小军”“银行小期”：“小”的 x 音和“七”的 q 音主要在 4 kHz 以上，被窄带切掉了。
7. **常开 30 分钟稳定。** 在用户会话里麦克风连续打开 30 分钟，没有溢出、丢帧或中断，音箱没有休眠或断开；期间 6 次播放全部出声。
8. **两个会话都能录放。** SSH 所在的会话 0 能枚举、录音，播放出声 3 次；用户登录会话（会话 1）常开 30 分钟，6 次播放全部出声。
9. **偶发失声，原因未查明。** 21:33（会话 0）和 21:38（会话 1）两次向立体声输出播放，程序无报错但音箱无声；之后同样的操作都正常，1 分钟间隔下也没能复现。这两次没有读取端点电平表，不能确定 Windows 是否送出了音频。

## 测试 A：麦克风关闭时的立体声播放

向输出 11 播放“测试，这是立体声输出……”和 5 声测试音，以及一段天气回答（均为 sherpa-tts 生成，44.1 kHz 播放）。

- 第 1、2 次（21:33、21:38）：无声，见结论 9。
- 第 3、4 次（会话 0）：出声；端点电平表峰值 0.48–0.50，内置扬声器为 0；用户听到 5 声测试音。
- Windows 端点状态：活动、音量 49%、未静音，是系统默认输出。

## 测试 B：麦克风打开时播放

另一个进程打开输入 12 录音 31.3 秒（无溢出、无丢帧），期间向输出 11 播放同样两段。

- 用户只听到 1–2 声测试音，语音音质与 A“差不多”。
- 麦克风录音的电平时间线：无人说话时 RMS 约 -29.7 dBFS；播放时 -17～-19 dBFS，峰值 -3～-6 dBFS；1 kHz 测试音 -7 dBFS，3 kHz 测试音 -16～-22 dBFS。
- 麦克风关闭后 1 分钟向立体声输出播放：正常出声。

## 测试 B（长时间）：常开 30 分钟

计划任务在用户会话（会话 1）运行 [`p05-soak.json`](../deploy/voice-terminal/p05-soak.json)：麦克风常开 30 分钟，每 5 分钟向输出 11 播放一次提示语 + 测试音，共 6 次。是否出声由麦克风录到的回放判断。

| 指标 | 结果 |
| --- | --- |
| 时间 | 22:00:06–22:30:06，1800.06 秒 |
| 采样帧 | 收到 14,393,760 帧，比理论值少 6,744 帧（0.84 秒），全部是开头建立通话链路的时间 |

## 测试 E：降噪对照语料

用户按 [`corpus.txt`](../deploy/voice-terminal/corpus.txt) 读 20 句（含 5 句“你好小七”），每遍 130 秒，开始和结束由音箱语音提示：

| 遍 | 距离 | 环境 | 录音 |
| --- | --- | --- | --- |
| 1 | 1 米 | 安静 | `take1-1m-quiet.wav`，句首几句读得较晚，部分被漏掉 |
| 2 | 3 米 | 安静 | `take2-3m-quiet.wav` |
| 3 | 1 米 | 手机播放播客 / 音乐 | `take3-1m-phone.wav` |
| 4 | 3 米 | 手机播放播客 / 音乐 | `take4-3m-phone.wav` |

处理流程：8 kHz → soxr 升采样到 16 kHz → 前端版本 → Silero VAD 切句 → SenseVoice int8（与后端同一模型，关闭 ITN）→ 与参考文本比较错字率；唤醒用桥接的 sherpa-onnx 唤醒模型（`keywords_score` 2.0，`keywords_threshold` 0.2）在整段上运行。

| 版本 | 安静底噪 | 平均错字率 | 识别出“你好小七” | 唤醒命中（阈值 0.2 / 0.1 / 0.05） |
| --- | --- | --- | --- | --- |
| 不处理 | -29.8 dBFS | 11.7% | 11/20 | 2 / 2 / 4 次（共 20） |
| 高通 | -43.7 dBFS | 12.8% | 8/20 | 2 / 3 / 3 |
| WebRTC 降噪 + 高通 | -56.4 dBFS | 11.7% | 9/20 | 4 / – / – |
| WebRTC 降噪 + 高通 + 自动增益 | -48.5～-50.5 dBFS | 10.7% | 10/20 | 5 / 7 / 9 |
| 频谱降噪 0.6（离线） | -40.7 dBFS | 10.7% | 7/20 | 3 / – / – |
| 频谱降噪 0.95（离线） | -58.8 dBFS | 51.1% | 5/20 | 3 / – / – |

- 所有版本都没有出现其他唤醒词的误触发。
- 强力频谱降噪会把人声一起切掉，VAD 只切出 4–6 段，不可用。
- 样本量小（每个版本 20 次唤醒词），只用来判断量级；但不论怎么处理，唤醒命中都不超过 45%。

## 对方案的影响

1. 这台音箱的麦克风不适合做带本地唤醒的终端。建议输入改用 USB 麦克风（16 kHz 以上，最好是带硬件降噪 / 回声消除的会议全向麦），蓝牙音箱只做输出。这样蓝牙一直处在立体声模式，同时解决窄带收音和通话模式播放两个问题。如果坚持纯蓝牙，需要换一台支持宽带语音（mSBC）的音箱重测。
2. 音频前端默认用“高通 + WebRTC 降噪 + 自动增益”；不使用强力频谱降噪。
3. 播放时暂停收音（已在方案中）对这台音箱是必须的。
4. 终端只绑定一个蓝牙“耳机”输出端点，不需要单独处理 Hands-Free 端点。
5. 运行会话：会话 0 和会话 1 都能录放。会话 0 不依赖登录和远程桌面，P1 优先尝试以后台任务方式在会话 0 运行，并验证重启后不登录时的录放；不行再改为控制台自动登录 + 用户会话。

# 小爱音箱“你好小七”唤醒率测试（2026-10-05）

## 现象

对小爱音箱（OH2P，客厅）喊“你好小七”，常常第一遍没反应，第二遍才唤醒；唤醒后不说话，20 秒后说“主人再见，拜拜”。

## 日志结论

- 每次没反应时，音箱录音正常（16 kHz、无断流、无 ALSA 错误），桥接收到的音频全部送进了唤醒模型（`kws_mode=active`，RTF 0.14，无错误、无积压）。模型处理了这段声音，只是分数没过阈值。
- 退出对话后第一遍也可能直接唤醒；对话开始前、KWS 已连续运行 8 分钟时也会漏。所以不是“退出后没重新开始检测”的状态问题。
- “拜拜”是正常的 20 秒无语音超时：唤醒后那 20 秒录音只有环境底噪。

## 测试方法

1. 暂停桥接服务（避免被唤醒后进入对话），在音箱上用 `arecord` 并行录两路：
   - `-D noop -f S32_LE -r 16000 -c 1`：客户端现在送给唤醒模型的数据（再按客户端的 `>>8` 换算成 16 位）；
   - `-D Capture -f S32_LE -r 48000 -c 4`：原始 4 声道。
2. 站在平时的位置，正常音量说 10 遍，再大声喊 10 遍以上（实际切出 23 段）。
3. 在桥接镜像里用同一个 sherpa-onnx 1.12.32 模型和参数回放，统计每一段是否被认出。
4. 开着电视录 20 分钟（只录 `noop` 一路），回放统计误唤醒。

## 结果

| 送给模型的音频 | 阈值 | 认出 | 正常音量 | 大声喊 |
|---|---|---|---|---|
| 现在线上的 | 0.2 | 13/23 | 7/10 | 6/13 |
| 现在线上的 | 0.15 | 15/23 | 8/10 | 7/13 |
| 现在线上的 | 0.1 | 16/23 | 8/10 | 8/13 |
| 现在线上的 | 0.08 | 17/23 | 9/10 | 8/13 |
| 现在线上的 | 0.05 | 19/23 | 10/10 | 9/13 |
| 原始数据，单个麦克风，不削波 | 0.2 | 14–17/23 | | |
| 原始数据，单个麦克风，不削波 | 0.1 | 19–21/23 | | |

电视录音 20 分钟：阈值 0.2、0.15、0.1、0.05、0.03、0.02 都没有误唤醒（7 个唤醒词都没有）。

结论：分数普遍卡在 0.2 附近，阈值是主要因素。线上改为只给“你好小七”设 `keyword_thresholds: {"你好小七": 0.05}`，与书房蓝牙音箱终端的阈值一致。

## 第二轮：随机漏识别

调到 0.05 后实测约 10 次，开头几次仍有漏，后面 6 次全中。离线发现，同一遍话能否认出取决于它前面的音频：每遍单独检测时，带 1 秒前文认出 20/23，带 3 秒只有 10/23，而且这时 0.05 和 0.1 的结果完全一样。也就是说，“你好小七”这条候选在搜索中途被丢掉了，跟阈值无关。

编码器每 320 ms 处理一块（`decode_chunk_len=32`）。把每遍的起点在一个块内错开 8 种（2.0 s + k×40 ms 前文），阈值 0.05：

| 设置 | 8 种起点的平均认出 |
|---|---|
| 候选 8（原来） | 19.9/23 |
| 候选 16 | 20.9/23 |
| 候选 8，两路错开 160 ms，任一路认出即唤醒 | 21.5/23 |
| 候选 16 + 两路错开 160 ms | 22.5/23 |
| 加分 `keywords_score` 3 或 4（候选 8） | 更差 |

最后一行用实际部署的 `sherpa.py` 复测：平均 22.6/23；按线上方式连续检测认出 21/23，正常音量 10/10；20 分钟电视录音没有误唤醒（阈值 0.02 时也没有）。线上配置为 `max_active_paths: 16`、`stream_offsets_ms: [0, 160]`，唤醒检测 RTF 从 0.14 升到 0.28。

## 录音链路的其他问题（尚未处理）

- `noop` 是 `plug` → `dsnoop(hw:0,3)`，单声道输出是 4 个声道的平均，其中包括没有人声的回放参考声道 ch3。
- `plug` 的重采样（speexrate）只处理 S16，S32 数据只剩高 16 位；麦克风数据集中在低 24～26 位，所以客户端 `>>8` 之后有效精度约 8 位（16 位采样都是 256 的倍数，安静时约 4% 的采样正好是 0）。
- 人声峰值是 `>>8` 后上限的 4–6 倍，正常音量也有 2–5% 的采样被削平。
- 环境底噪主要是 150 Hz 以下的低频（约 65% 在 50 Hz 以下）。

单独去掉削波、恢复精度，在 0.2 下没有明显提升；改用单个麦克风有小幅提升。改这些需要重新编译音箱客户端，收益小于调阈值。
